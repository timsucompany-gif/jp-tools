# jp-tools ｜ 日本工具箱

一組給台灣人用的日本費用試算工具。純靜態 HTML／CSS／JS，零建置步驟、零外部框架。

> **⚠️ 目前是草稿階段，整站掛著 `noindex`。**
> 住宿與鐵路的費率已查證，**租車全部仍是估計值**。上線前的檢查清單在最下面。

---

## 這組工具在做什麼

只做「使用者自己算不出來」的部分。加總跟除以人數，手機計算機就能做；
真正麻煩的是各自治體不同的稅、藏在細項裡的保險費，
以及「這張票券到底該不該買」這種要比價才知道的決定。

三條貫穿全站的設計原則：

1. **只補上會被漏掉的錢。** 每個工具都把「自己估預算時會整筆忘掉」的項目單獨標出來。
2. **誠實顯示不確定性。** 用平均值推的和逐項算的分得清清楚楚。
   沒把握比使用者更準的項目（例如餐費）就明說不做精算 —— 假的精確感比誠實的粗估更糟。
3. **費率會過期，所以標日期。** 每一項都記錄查證日與下次複查日。

## 目錄結構

```
jp-tools/
├── index.html              工具總覽（純靜態卡片，不載計算邏輯）
├── shared/                 ← 全站共用，改一次到處生效
│   ├── rates.js            所有費率資料（未來可拆成 data/*.json）
│   ├── core.js             純計算函式、匯率、幣別、數字動畫（零 DOM 依賴的部分）
│   ├── calc.css            共用樣式
│   ├── rental-module.js    租車詳細模組
│   ├── lodging-module.js   住宿詳細模組
│   └── rail-module.js      鐵路詳細模組
├── travel/
│   ├── trip-cost/          整趟旅費估算（wizard，主入口）
│   ├── rental-car/         自駕總成本 ＋ Expressway Pass
│   ├── accommodation/      住宿實付金額 ＋ 宿泊稅
│   └── jr-pass/            JR Pass 值不值得買
├── living/                 （待做）租屋初期費用、手取り試算
├── finance/                （待做）日圓台幣換算
└── .nojekyll
```

### 為什麼要有 `shared/`

三個詳細模組共用同一套介面 —— `mount()` / `setContext()` / `getResult()`。
同一份程式碼有兩個入口：

- **獨立頁**（`travel/rental-car/`）：模組自己擁有天數、人數等欄位，是 SEO 入口
- **wizard 內**（`travel/trip-cost/`）：這些欄位由 wizard 統一注入，模組不重複問

如果每個工具各寫各的、每個都自己問一次天數人數，就永遠組不成 wizard，
費率也會散成七份、季更新直接破功。**這層是整個結構的重點。**

### 加一個新工具

1. 在對應分類下建資料夾（英文小寫、連字號），資料夾名就是網址
2. `index.html` 用 `../../shared/` 引入共用檔
3. 需要新的計算邏輯就在 `shared/core.js` 加純函式（不要碰 DOM）
4. 需要可重用的 UI 就照現有三個模組的介面寫一個新模組
5. 在 `index.html` 總覽加一張卡片

## 本機預覽

```
python -m http.server 4321
```

然後開 http://localhost:4321/

也可以直接雙擊 `index.html`。共用檔是用 `<script src>` 載入的，
`file://` 底下可以正常運作 —— 這也是費率做成 `.js` 而不是 `.json` 的原因
（`file://` 下 `fetch()` 讀 JSON 會被 CORS 擋掉）。

## 季更新（約 1 小時）

工具站沒有故事可以撐，**唯一的信任來源就是數字是對的、是新的**。
資料放著半年不動，工具就從資產變成負債。

| 項目 | 查哪裡 | 頻率 |
| --- | --- | --- |
| 各管道租車行情 | 照固定的基準查詢條件重抓報價 | 每季 |
| 汽油單價 | 資源エネルギー庁 週次調查 | 每季 |
| Expressway Pass 方案 | NEXCO 東／中／西 官方頁 | 每季 |
| 宿泊稅級距 | 各自治體官網 | 每季 |
| Airbnb 行情與清潔費 | 同條件抓房源 | 每季 |
| Airbnb 服務費模式 | ⚠️ 過渡期，最該重查的一項 | 每季 |
| CDW／NOC、都市停車行情 | 業者官網 | 每年 |

**⚠️ 更新資料後，四個頁面的 `?v=YYYYMMDD` 必須一起改。**
瀏覽器會把 `shared/*.js` 快取住 —— 版本號不改，辛苦更新的費率傳不到使用者手上，
整輪季更新等於白做。

## 已知限制

- **地區版 Pass 的判斷偏保守。** 目前用單一 `region` 標記判斷適用性，
  但實際 Pass 涵蓋範圍會跨區（例如 JR East 的 Pass 涵蓋東京→長野）。
  現在把跨區路線一律只讓全國版適用 —— 寧可少推薦，也不要推薦到用不了的 Pass。
- **每日當地交通是估計值**（都市 800／山區 1,500），非逐項查證。
- **Airbnb 平台服務費處於制度過渡期**，預設 0 並在畫面上說明，讓使用者自己對結帳頁。
